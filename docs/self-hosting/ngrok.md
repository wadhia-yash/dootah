# ALPHA / CLEAN-ROOM VALIDATION USING NGROK

This supported local-validation path uses an authenticated ngrok agent on the
Docker host. It is not the production deployment architecture. Production remains
HTTPS reverse proxy → Cloud → private xprem/PostgreSQL; see
[deployment](../../v2/deploy/DEPLOYMENT.md).

```text
Android / customer CLI -> public ngrok HTTPS URL
                       -> host 127.0.0.1:18080 -> Caddy :80
                                               -> private Cloud :3100
                                               -> private xprem / PostgreSQL
```

ngrok supplies **HTTPS transport only**. Its publicly trusted server certificate is
checked by curl, Node and Android's normal platform trust. The separate **Dootah OTA
update-signing certificate** is generated by per-app xprem provisioning and embedded
through `dootah.publicCertificate`; it verifies updates and signed rollback. Do not
use an ngrok TLS certificate as the OTA certificate or export either private key.

A successful trial proves **clean-room HTTPS OTA acceptance through a publicly
trusted tunnel**. It does not prove production self-host deployment, custom-domain
TLS, Maven Central/JFrog availability or Internet-scale production operation.

## Prepare a fresh trial

Use the [quickstart prerequisites](../getting-started/quickstart.md#prerequisites-and-tooling),
Docker with Compose 2.24.4+ (`!override` support), Git, Python 3, Bash, curl, and an authenticated ngrok installation.
Use a dedicated Bash shell. Run `ngrok version` and `ngrok config check`; do not
print the configuration or ask anyone to share their auth token. If authentication
is missing, stop with **USER ACTION REQUIRED**: configure ngrok locally using the
account dashboard's setup instructions. Never put the token in Dootah files or logs.

Start in a new clean checkout of the reviewed commit. For example, clone the source
checkout with `git clone --no-local --no-hardlinks SOURCE_CHECKOUT NEW_CHECKOUT`,
then check out the reviewed SHA there. Verify `git status` and `git rev-parse HEAD`.
No ignored producer outputs, old Maven repositories or acceptance workspaces are inputs.

```sh
export DOOTAH_REPO="$PWD"
umask 077
export DOOTAH_WORK="$(mktemp -d "${TMPDIR:-/tmp}/dootah-ngrok.XXXXXXXX")"
export COMPOSE_PROJECT_NAME="$(basename "$DOOTAH_WORK" | tr '[:upper:]' '[:lower:]' | tr '.' '-')"
export GRADLE_USER_HOME="$DOOTAH_WORK/gradle-producer"
export npm_config_cache="$DOOTAH_WORK/npm-cache"
export DOOTAH_PRIVATE="$DOOTAH_WORK/customer"
mkdir -p "$DOOTAH_WORK/operator" "$DOOTAH_WORK/evidence" "$GRADLE_USER_HOME" "$npm_config_cache"
mkdir -p "$DOOTAH_PRIVATE/publisher" "$DOOTAH_PRIVATE/native-release"
unset NODE_EXTRA_CA_CERTS NODE_TLS_REJECT_UNAUTHORIZED
```

Use unused loopback ports 18080 (Caddy) and 4040 (ngrok's local agent API). Do not
stop unrelated services or tunnels to reclaim them. If your ngrok configuration
uses another agent API address, use that local address in the commands below.
Do not publish the agent API. Its HTTP address is local operator control traffic,
not the public Dootah endpoint.

## Configure and start the private backend

The repository-supported [Compose overlay](../../v2/deploy/compose.ngrok.yaml) and
[Caddy configuration](../../v2/deploy/Caddyfile.ngrok) publish **only Caddy**, at
`127.0.0.1:18080`. Cloud retains only its internal ingress/backend networks; Cloud,
xprem and PostgreSQL have **no host ports**. The proxy reaches `cloud:3100` privately.
The overlay replaces both production port bindings rather than appending a port.
Do not run the base Compose `up proxy` command for this trial.

For the initial internal/loopback health check only, use the reserved non-routable
HTTPS origin below. No app, delivery binding or APK may be created with this value.
After ngrok starts, replace it with the final URL and recreate Cloud/xprem before
customer onboarding. Production HTTPS origin validation remains enabled.

```sh
export DOOTAH_CLOUD_ORIGIN=https://bootstrap.invalid
cat > "$DOOTAH_WORK/operator/deploy.env" <<EOF
COMPOSE_PROJECT_NAME=$COMPOSE_PROJECT_NAME
DOOTAH_SITE=localhost
DOOTAH_CLOUD_ORIGIN=$DOOTAH_CLOUD_ORIGIN
DOOTAH_OPERATOR_EMAIL=operator@example.test
DOOTAH_SECRETS_DIR=$DOOTAH_WORK/operator/secrets
DOOTAH_CADDYFILE=$DOOTAH_REPO/v2/deploy/Caddyfile.ngrok
DOOTAH_BIND_IP=127.0.0.1
DOOTAH_HTTP_PORT=8080
DOOTAH_HTTPS_PORT=8443
EOF
python3 "$DOOTAH_REPO/v2/deploy/ops.py" secrets "$DOOTAH_WORK/operator/secrets"
dc() { docker compose --env-file "$DOOTAH_WORK/operator/deploy.env" -f "$DOOTAH_REPO/v2/deploy/compose.yaml" -f "$DOOTAH_REPO/v2/deploy/compose.ngrok.yaml" "$@"; }
op() { python3 "$DOOTAH_REPO/v2/deploy/ops.py" --env "$DOOTAH_WORK/operator/deploy.env" "$@"; }
dc config --quiet
git clone https://github.com/mercuretechnologies/xprem "$DOOTAH_WORK/xprem-upstream"
git -C "$DOOTAH_WORK/xprem-upstream" checkout --detach b46e13569f5734a66ed903f75f51b87b78e80c1b
export DOOTAH_GO_MOD_VOLUME="$COMPOSE_PROJECT_NAME-go-mod"
export DOOTAH_GO_BUILD_VOLUME="$COMPOSE_PROJECT_NAME-go-build"
export DOOTAH_BUILD_EVIDENCE="$DOOTAH_WORK/evidence/server-build"
bash "$DOOTAH_REPO/v2/deploy/build.sh" "$DOOTAH_WORK/xprem-upstream"
dc up -d postgres
dc exec -T postgres pg_isready -U postgres -d postgres
op bootstrap
dc run --rm cloud-migrate
dc run --rm xprem-migrate
op grant-xprem
dc run --rm cloud-user
dc up -d xprem cloud proxy
dc ps
curl --fail http://127.0.0.1:18080/live
curl --fail http://127.0.0.1:18080/ready
```

Wait for PostgreSQL readiness before bootstrap, and for all service health after
startup. The host probes must return 200 with plain `live` and `ready` bodies.
Only the host-loopback hop from ngrok to Caddy uses HTTP; clients use public HTTPS.
The existing Caddy edge network provides host ingress, while its internal ingress
network reaches Cloud. xprem and PostgreSQL remain on the private backend network.

## Obtain the final HTTPS URL

Start exactly one HTTP tunnel, targeting only the healthy Caddy loopback listener.
Disable request inspection so this local agent does not retain request bodies or
credentials. Do not run `ngrok start --all`, TCP tunnels or a tunnel to xprem/DB.

```sh
ngrok http http://127.0.0.1:18080 --inspect=false --log=stdout --log-format=json > "$DOOTAH_WORK/operator/ngrok.private.log" 2>&1 &
export DOOTAH_NGROK_PID=$!
curl --fail http://127.0.0.1:4040/api/tunnels > "$DOOTAH_WORK/operator/tunnels.json"
export DOOTAH_CLOUD_ORIGIN="$(python3 - "$DOOTAH_WORK/operator/tunnels.json" <<'PY'
import json, sys
from urllib.parse import urlsplit
tunnels = json.load(open(sys.argv[1]))['tunnels']
assert len(tunnels) == 1, 'Expected exactly one tunnel; inspect locally without sharing credentials'
t = tunnels[0]
assert t['config']['addr'] == 'http://127.0.0.1:18080', 'Tunnel must target only loopback Caddy'
u = urlsplit(t['public_url'])
assert u.scheme == 'https' and u.hostname and not u.username and not u.password and not u.path and not u.query and not u.fragment
print(t['public_url'])
PY
)"
export DOOTAH_CLOUD_URL="$DOOTAH_CLOUD_ORIGIN"
printf '%s\n' "$DOOTAH_CLOUD_ORIGIN"
```

Wait for the agent API/tunnel to appear and repeat the query if it is still starting.
If ngrok reports an account/authentication requirement, stop for the operator to
complete local setup; do not request their token. Keep private agent logs outside Git.
An upstream-unavailable response now is a preflight failure. Obtain the final URL
before configuring any app, delivery binding or accepted APK.
Keep this agent process and URL for the whole trial. If it changes after the accepted
installation, stop; do not rebuild/reinstall to repair the trial.

Replace the bootstrap origin in the private environment file, then recreate both
services so their advertised origins agree. Keep the same ngrok process alive.

```sh
python3 - "$DOOTAH_WORK/operator/deploy.env" <<'PYORIGIN'
import os, pathlib, sys
p = pathlib.Path(sys.argv[1])
p.write_text('\n'.join('DOOTAH_CLOUD_ORIGIN=' + os.environ['DOOTAH_CLOUD_ORIGIN']
    if line.startswith('DOOTAH_CLOUD_ORIGIN=') else line
    for line in p.read_text().splitlines()) + '\n')
PYORIGIN
dc up -d --force-recreate xprem cloud
dc up -d proxy
```

The final HTTPS origin drives Cloud's `DOOTAH_CLOUD_ORIGIN` and xprem's advertised
`BASE_URL`. Cloud's `DOOTAH_XPREM_ORIGIN` remains `http://xprem:3100`.
The operator tool uses the base Compose file; its `binding-put` recreates only
Cloud, whose configuration is unchanged by this overlay. Continue using `dc` for
stack lifecycle operations, especially proxy startup; do not use the base-only
backup/restore lifecycle during this disposable trial.

## Live HTTPS preflight before SDK staging or APK build

```sh
curl --fail "$DOOTAH_CLOUD_URL/live"
curl --fail "$DOOTAH_CLOUD_URL/ready"
node --input-type=module -e 'for (const p of ["/live", "/ready"]) { const r = await fetch(process.env.DOOTAH_CLOUD_URL + p); if (r.status !== 200) throw Error(p + " status " + r.status); console.log(p, r.status, await r.text()); }'
curl --fail http://127.0.0.1:4040/api/tunnels > "$DOOTAH_WORK/operator/tunnels.json"
dc ps
```

Require HTTP 200 with plain `live` and `ready` bodies from both public probes and Node.
Recheck that the agent API lists only the HTTPS tunnel to `http://127.0.0.1:18080`
and verify actual Docker bindings (image `5432/tcp` metadata is not a host mapping):

```sh
for service in cloud xprem postgres proxy; do
  docker inspect "$(dc ps -q "$service")" --format '{{.Name}} {{json .HostConfig.PortBindings}} {{json .NetworkSettings.Ports}}'
done
node --test "$DOOTAH_REPO/v2/deploy/ngrok.test.mjs"
```

Cloud/xprem/PostgreSQL must have no host bindings. Only Caddy may publish a port,
with `HostIp` exactly `127.0.0.1` and `HostPort` `18080`. Do not proceed on a missing
listener or any broader binding.
No xprem or PostgreSQL tunnel is created by these commands. Keep unrelated ngrok
agents/endpoints out of this trial and audit any preexisting account routing separately.

Normal system/platform HTTPS certificate verification is required throughout.
Do not use insecure curl options, custom-CA bypasses, disabled Node TLS verification,
global cleartext permission or Android trust-manager overrides. If an ngrok limit,
interstitial page, account policy or network error replaces the expected API response,
stop and diagnose it; HTML is not a successful Cloud health response.

Build the customer CLI using the quickstart's `test installDist` and PATH commands
with the fresh producer Gradle home, then verify authenticated access to the same URL:

```sh
dootah login --email operator@example.test --password-file "$DOOTAH_WORK/operator/secrets/initial-password" --session-file "$DOOTAH_PRIVATE/session"
dootah org list --session-file "$DOOTAH_PRIVATE/session"
```

Only after this preflight passes, stage `0.1.0-alpha.1` into a new directory under
`DOOTAH_WORK` using the [official staging commands](../getting-started/quickstart.md#current-pre-publication-setup).
Never use `android-sdk/build/maven`, `mavenLocal()` or `0.7.5-local` for this trial.

## Create the app binding and build the final native baseline

```sh
dootah org create --name 'Ngrok alpha organization' --session-file "$DOOTAH_PRIVATE/session"
export DOOTAH_ORGANIZATION='RETURNED_ORGANIZATION_ID'
dootah app create --name 'Ngrok alpha Android app' --session-file "$DOOTAH_PRIVATE/session"
export DOOTAH_APP_ID='RETURNED_APP_ID'
dc run --rm --no-deps -T xprem -provision -app-name 'Ngrok alpha Android app' -channel development > "$DOOTAH_WORK/operator/app.credentials.json"
op binding-put "$DOOTAH_APP_ID" "$DOOTAH_WORK/operator/app.credentials.json"
op bindings-list
curl --fail "$DOOTAH_CLOUD_URL/ready"
```

`binding-put` records the final public origin from `deploy.env` and the private
`http://xprem:3100` binding base. `bindings-list` prints these non-secret endpoints.
Never print the provisioning file: it contains an API key alongside the public OTA
signing certificate. After creating your fresh Compose application and setting
`DOOTAH_APP_ROOT` to its root, extract only that public OTA certificate:

```sh
python3 - "$DOOTAH_WORK/operator/app.credentials.json" "$DOOTAH_APP_ROOT/app/update-certificate.pem" <<'PY'
import json, pathlib, sys
value = json.loads(pathlib.Path(sys.argv[1]).read_text())
pathlib.Path(sys.argv[2]).write_text(value['certificate'])
PY
export GRADLE_USER_HOME="$DOOTAH_WORK/gradle-consumer"
mkdir -p "$GRADLE_USER_HOME"
```

Use the quickstart's staged exclusive repositories, plugin and native Application
integration. Set `updateUrl = System.getenv('DOOTAH_CLOUD_URL') + '/manifest'` with
the final URL already exported. Use normal Android platform HTTPS trust; do not
copy the private-CA trial's debug manifest/resources. Keep the OTA certificate at
`publicCertificate = file('update-certificate.pem')`.

Before building, confirm this agreement:

| Setting | Required value |
| --- | --- |
| Cloud public origin / CLI `DOOTAH_CLOUD_URL` | Final ngrok HTTPS origin |
| xprem advertised `BASE_URL` | Same final HTTPS origin, supplied by Compose |
| Binding `publicOrigin` | Same final HTTPS origin, shown by `bindings-list` |
| Android `updateUrl` | Same origin plus `/manifest` |
| Private xprem origin / binding `base` | `http://xprem:3100`, never an ngrok URL |
| Channel | `development` consistently in native app, provisioning and retained environment |

Now follow quickstart build/retention, import/registration and enrollment. The
environment contract derives from the exact retained native build, so registration
follows retention; do not invent a contract before the APK exists. Keep the native
enrollment UI in the baseline. Never embed ngrok auth, publisher tokens or private keys.

At physical-device work, run `adb devices -l`. If the Samsung is absent, stop with:
**USER ACTION REQUIRED: connect/unlock the Samsung and enable USB debugging.**
Never request its PIN. With the device available, install the accepted APK once,
record its SHA-256 and install timestamp, verify the native baseline, and enroll.
All trust/origin configuration must already be final. From that installation onward,
do not rebuild/reinstall the APK or clear app data.

## OTA, offline check, rollback and cleanup

Follow the quickstart's supported source edit, analyze, Cloud publish and rollout.
Verify actual native rendering, signature acceptance, activation and health on the
same installed APK; server receipts alone are insufficient. Record check/available/
download-start/download-complete/activated/healthy telemetry where supported.

For the offline-cache check, keep ngrok running to preserve its URL and use
`dc stop cloud` to make only Dootah retrieval unavailable. Restart the app normally
and verify cached OTA, then restore with `dc up -d cloud` and verify `/ready` over
HTTPS again. This is a retrieval-outage test, not a claim that all device networking
was disabled. No radio settings or adb reverse rules need to change.

Use the **customer CLI** rollback command, inspect the signed operation, allow an
online device check, restart and verify native restoration. Keep the same APK and
install timestamp. Test documented unsupported-edit refusal and sandbox isolation
without weakening any check. Preserve sanitized evidence and release hashes.

After rollback, stop the test app and stop only this trial's tunnel and stack:

```sh
export DOOTAH_ANDROID_PACKAGE='YOUR_TEST_APPLICATION_ID'
adb shell am force-stop "$DOOTAH_ANDROID_PACKAGE"
kill "$DOOTAH_NGROK_PID"
wait "$DOOTAH_NGROK_PID" || true
dc down --volumes --remove-orphans
docker volume rm "$DOOTAH_GO_MOD_VOLUME" "$DOOTAH_GO_BUILD_VOLUME"
```

If stopping early, clean up only resources actually created. Do not stop other
ngrok agents, delete their configuration or revoke account credentials. Remove any
trial-specific adb rules if you separately created them; this route creates none.
Dispose of temporary operator secrets after preserving necessary private release
evidence outside Git. Never commit raw logs, tokens, private keys, databases or APKs.
