# Operator secret inventory

Keep this directory empty in Git. Generate the real directory **outside the checkout**
with `ops.py secrets /srv/dootah/operator/secrets`. Generation refuses an existing
directory, uses OS randomness, creates mode-0700 directories and mode-0600 files,
and never prints values. Do not put real values in `.env.example`.

| File / material | Consumer / lifetime |
| --- | --- |
| `postgres-password` | PostgreSQL bootstrap superuser; recovery administration only |
| `cloud-owner-password`, `cloud-owner-url` | Explicit Cloud migration/user provisioning job only |
| `cloud-runtime-password`, `cloud-runtime-url` | Cloud non-owner runtime role |
| `xprem-owner-password`, `xprem-owner-url` | Explicit xprem migration job only |
| `xprem-runtime-password`, `xprem-runtime-url` | Private xprem signing/storage runtime |
| `master-key` | 32-byte base64 xprem database encryption key; **non-regeneratable** |
| `xprem-jwt` | Random upload-token signing secret; coordinate rotation with pending uploads |
| `initial-password` | Bootstrap users; unique high-entropy generated password, distribute privately |
| `bindings.json` | Cloud app → private xprem identity, certificate and API key; operator-owned |
| Per-app signing keys | Generated by upstream xprem and encrypted in its PostgreSQL database |
| Cloud session/API credentials | Random opaque values; only digests in Cloud DB; no static session signing secret |
| Customer backend scoped token | Customer backend secret store; never APK, binding, image or portable artifact |
| Enrollment ticket | Short-lived single-use response; deliver privately to authenticated native client |

Compose mounts only the secrets needed by each service/job. Runtime services do not
receive owner URLs, owner passwords, bootstrap password or PostgreSQL superuser secret.
File mounts retain host ownership. Entrypoints validate mode 0400/0600, copy into a
private tmpfs directory, and drop to UID/GID 10001. The HTTP processes run non-root.
Host root and Docker administrators remain trusted. These are ordinary protected
files, not an encrypted secret manager. Protect and encrypt off-host backups.

Cloud supports `DOOTAH_CLOUD_DATABASE_URL_FILE` and `DOOTAH_INITIAL_PASSWORD_FILE`;
xprem supports `DB_URL_FILE`, `DB_KEYS_MASTER_KEY_B64_FILE`, `JWT_SECRET_FILE` and
`ADMIN_PASSWORD_FILE`. The corresponding environment variable can be injected instead;
setting both forms is rejected. Prefer files: environment values are visible through
container inspection. Compose intentionally uses files. No `_FILE` shell sourcing occurs.

DB password rotation is an explicit DBA operation: alter the role through a private
connection, update the matching password/URL files, then recreate its service/job.
Bootstrap does not silently change existing role passwords. Do not regenerate the
master key to rotate database passwords. Master-key re-encryption and installed app
signing-key rotation are outside this alpha. Losing either the master key or the
corresponding encrypted signing-key database can make updates to existing APKs
impossible. Restore both from the same backup set.
